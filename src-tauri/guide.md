# knock — 에이전트용 사용 안내

knock 은 사람의 승인·결정이 필요할 때 채팅 대신 데스크톱 창(그리고 설정에 따라 Slack DM)을 띄우는 CLI 다.
사용자는 딴 일을 하는 중이라 채팅 질문은 놓친다. 승인·선택이 필요하면 채팅으로 묻지 말고 knock 을 쓴다.

## 언제 쓰나

- **승인(annotate --gate)**: 되돌리기 어렵거나 바깥에 영향을 주는 행동 직전 (PR 머지, 배포, 삭제, 운영 변경, 권한 확장).
  본문에는 무엇을 하려는지, 근거, 영향, 롤백을 적는다.
- **질문(ask)**: 사용자가 방향을 골라야 할 때. 선택지가 둘 이상이고 판단 근거가 필요한 경우.
- 사용자가 이미 명시적으로 허락한 작업, 되돌리기 쉬운 로컬 작업에는 쓰지 않는다.

## 승인 요청: `knock annotate <file.md> --gate --json`

본문은 markdown 파일로 만들어 넘긴다. 결정은 표준출력 JSON 한 줄로 온다.

| 사용자가 한 일 | 출력 |
|---|---|
| 승인 | `{"decision":"approved"}` |
| 변경 요청 (의견 입력) | `{"decision":"annotated","feedback":"..."}` |
| 닫기 · Esc | `{"decision":"dismissed"}` |

- `approved` 이면 승인된 범위만 진행한다. `annotated` 면 feedback 을 반영해 다시 올린다.
- `dismissed` 는 답이 아니다. 기본값을 가정하지 말고 멈추거나 다시 묻는다.

### 옵션

| 옵션 | 의미 |
|---|---|
| `--gate` | 승인 버튼을 보여준다. 없으면 읽기·의견 전용 뷰어다 |
| `--json` | 결정을 JSON 으로 받는다. 에이전트는 항상 붙인다 |
| `--title T` | 창 제목. 기본은 파일 이름 |
| `--remote-approve` | 이 게이트를 Slack DM 으로도 보낸다 (`--gate` 필요). 아래 "Slack" 참고 |
| `--local-only` | 이 게이트는 Slack 으로 보내지 않고 맥 창에서만 받는다. `--remote-approve` 와 같이 쓸 수 없다 |
| `--action-url <URL>` | 승인하면 브라우저로 그 주소를 연다. 사용자가 웹 UI(Scalr Apply, GitHub PR, ArgoCD, 대시보드)에서 직접 눌러야 할 때 쓴다. `file:///abs/path.html` 같은 로컬 문서도 된다 |
| `--checklist` | 승인 뒤에도 요청을 큐에 "진행 중"으로 남긴다. 사용자가 브라우저에서 여러 단계를 밟는 동안 절차를 다시 볼 수 있고, "완료" 를 눌러야 응답이 온다 |
| `--touch-id` | 지문(Touch ID / Windows Hello)으로만 승인받는다. 운영 변경·권한 확장·삭제 같은 critical 게이트에 쓴다. Slack 으로는 가지 않는다 |
| `--view <FILE>` | 자립형 HTML(다이어그램, 시안)을 요청 옆 패널에 띄운다 |
| `--merge-toggle` | PR 머지 게이트에 "이후 머지 자동 승인" 토글을 보여준다 (사용자가 직접 켠다) |

## 객관식 질문: `knock ask <questions.json>`

사용자가 방향을 골라야 할 때 AskUserQuestion 대신 쓴다. 질문 JSON 은 임시 파일로 만들어 경로를 넘긴다 (끝나면 지운다).
최상위 `context` 에 배경·비교표·결론을 markdown 으로 담으면 선택지 위에 보인다. 결정 근거 없이 선택지만 던지지 않는다.

```json
{
  "context": "## 배경\n결정 근거를 markdown 으로.",
  "questions": [
    {
      "header": "구현 방향",
      "question": "어느 쪽으로 갈까?",
      "options": [
        { "label": "A안", "description": "설명" },
        { "label": "B안", "description": "설명" }
      ]
    }
  ]
}
```

- `header` 가 답의 키가 된다. 질문마다 다르게 쓴다. `label` 은 비어 있으면 안 된다.
- 기본은 **하나 선택**이다. 여러 개를 고르게 하려면 질문에 `"multiSelect": true`. 맥 창에는 항상 "기타"(직접 입력)가 붙는다.
- 질문은 한 번에 하나씩 보여준다 (←/→ 이동, 마지막에 요약). 질문이 하나면 요약 없이 바로 제출된다.
- 출력은 항상 JSON 이고 답은 **항상 배열**이다: `{"answers":{"구현 방향":["A안"]}}`. 하나만 골라도 `["A안"]`, "기타"로 쓴 글도 배열에 들어온다.
- 닫으면 `{"decision":"dismissed"}`. 기본값을 가정하지 말고 다시 묻거나 멈춘다.
- **Slack**: Slack 이 켜져 있고, 질문이 4개 이하이고, 질문마다 선택지가 1~24개(복수 선택은 10개)이고, 사용자 설정의 "항상 지문"이 꺼져 있으면 Slack 에도 올라가고 고른 라벨이 같은 모양의 `answers` 로 돌아온다. 단일 선택은 버튼(다시 누르면 바뀜), 복수 선택은 체크박스 + [제출], 질문이 여러 개면 모두 답해졌을 때(복수 선택이 있으면 [제출]) 한 번에 돌아온다. 질문마다 `기타…` 버튼이 모달 입력을 열고, 입력은 맥 창의 Other 와 같이 단일 선택은 선택을 대체하고 복수 선택은 체크와 함께 라벨 뒤에 붙는다. 한도를 넘는 질문은 맥 창에서만 받는다. `--remote-approve`·`remote_default` 와는 무관하게 이 조건만 본다.

## Slack 으로 보내려면

Slack 연동은 사용자가 settings 에서 켜야 동작한다 (꺼져 있으면 아래 옵션은 모두 무시되고 맥 창만 뜬다).
켜져 있을 때 `annotate --gate` 가 Slack DM 으로 가는 조건은 다음과 같다.

1. `--remote-approve` 를 붙이면 간다. Slack 으로 받고 싶으면 이 옵션을 명시한다. 사용자의 설정을 알 수 없어도 항상 통한다.
2. 사용자가 settings 에서 "모든 게이트를 Slack 으로" (`slack.remote_default`)를 켰다면 `--gate` 만으로도 간다. 이 경우 맥 창에서만 받아야 하는 게이트에는 `--local-only` 를 붙인다.
3. `--action-url` 의 호스트가 사용자가 허용한 목록(기본 `fnfcorp.scalr.io`)에 있으면 플래그 없이도 간다.

항상 Slack 에서 제외되는 것: `--touch-id` 게이트, 플러그인 훅(plan 승인)이 띄운 게이트, `--gate` 없는 뷰어. `--local-only` 는 위 1~3 보다 우선한다.
Slack 에는 본문을 마스킹해 최대 1,500자만 간다. 전체는 맥 창에서 본다.
맥 창과 Slack 의 결정은 먼저 도착한 한 번만 처리된다.

## 실행 방법

- **`run_in_background` 로 실행한다.** 사용자가 결정할 때까지 명령이 끝나지 않는다. 포그라운드로 돌리면 세션이 멈춘다. 결정이 오면 완료 알림이 오고, 그때 출력을 읽어 다음 행동을 정한다.
- 완료를 기다리는 동안 같은 승인을 다시 띄우지 않는다. 같은 건으로 게이트를 중복 생성하지 않는다.
- 승인 후 이어서 실행하는 명령이 있으면 그 명령 원문을 본문 맨 위(`▶️ 승인 시 실행`)에 적는다. "머지합니다" 같은 요약이 아니라 실제 명령이어야 무엇을 승인하는지 보인다.

## 본문에 쓰면 안 되는 것

- **비밀값(토큰, 비밀번호, API 키, 개인키, 연결 문자열)을 넣지 않는다.** 본문은 창과 Slack DM 에 그대로 보이고 파일로도 남는다. Slack 으로 갈 때 일부 패턴은 가려지지만 그것에 기대지 않는다. 필요하면 어디서 꺼내는지(이름, 경로)만 적는다.
- 본문 파일은 승인이 끝나면 지운다.

## 문제가 생기면

- `knock: cannot read ...` → 본문 파일 경로가 틀렸다.
- Slack 으로 안 간다 → settings 에서 Slack 사용이 꺼져 있거나 owner ID 가 비어 있다. 맥 창은 그대로 동작하니 거기서 받는다. 사용자에게 Slack 설정을 안내한다.
- `knock ctl list` 로 대기 중인 요청을 JSON 으로 볼 수 있다.
